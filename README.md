# 靓仔文案工作台（口播文稿 · 专家群聊系统）

七位 AI 专家（六位文案专家 + 一位事实核查员，各自带独立知识库/核查方法论）对你的一篇口播文稿进行**群聊式讨论**，直接给出「**改写后文本 + 一句话理由**」，输出完整讨论记录和各自终稿。群内还有一位**记录员（阿记）**：记录你采纳了谁的建议；在你给出实际效果数据后复盘评估「这条改动到底对不对」，并**把正/负反馈写进该专家的档案**——该专家下次讨论时会被强制带上"禁止清单/保持清单"；同时累计各专家**历史正确率排名**和**评分准确性排名**。

每位专家上线前会先执行「**知识内化**」：把原始知识库（txt/md/pdf/docx/图片OCR）**深度研读、消化吸收**，沉淀成一份专属的《个人知识档案》存到 `knowledge_digests/`。之后每次讨论，专家用的都是自己内化后的知识，而不是临时翻原始资料。

## 知识库怎么放

把资料丢进对应文件夹即可，**支持以下格式**（可混合）：

- 文本：`txt` / `md`
- 文档：`pdf` / `docx`
- 图片：`png` / `jpg` / `jpeg` / `bmp` / `webp` —— **截图会自动 OCR 识别文字**（超大图自动降采样），数据离线处理，不会上传

> 想换知识库目录：改 `config.json` 里对应专家的 `knowledge_path` 即可。

## 使用方法

### 方式一（推荐）：实时群聊窗口 ⭐

像真微信群一样：打开页面 → 把口播文稿粘贴进输入框 → 点「发送」→ 七位专家当场"打字"发言，三轮讨论 + 七份终稿实时呈现（阿骨先搭骨架定方向，阿证专职逐条核查论点是否真实可靠、是否踩平台合规红线）。专家发言一律用「**【改写】改好的文本 +【理由】一句话**」的短格式，直接给你可替换的成品，不啰嗦。

> **创作背景（全局植入）**：`config.json` 的 `context` 块保存了账号的核心信息（当前：账号主理人是深耕 8 年的玄学命理师·纯实战派；目标受众是 20-30 岁年轻女性）。这段信息会自动注入到**每位专家的系统提示、讨论三轮、评分、复盘、爆款学习**的所有 prompt 里，页面顶部也会显示提示条。专家的所有建议都会围绕"命理实战人设 + 年轻女性受众"展开，不会跑偏。改身份/受众只需改 `config.json` 的 `context`，页面自动同步。

```bash
# 启动实时群聊 Web 服务
python scripts/server.py
# 浏览器打开 http://127.0.0.1:8765
```

- 页面底部输入框粘贴文稿，按发送（或 Ctrl+Enter）
- 专家发言带「正在输入…」动画 + 打字机效果，讨论结束自动存档
- 每轮发言实时推送，刷新页面不丢消息（自动重放历史，且不会重复渲染）

### 记录员：采纳 → 评分 → 复盘 → 反馈闭环（阿记）

讨论结束后，页面每条专家发言/终稿下方会出现绿色「**采纳**」按钮：

1. **记录采纳**：点「采纳」→ 可写一句备注 → 阿记立即在群里发出「📋 采纳记录 #N」，写明来源专家、轮次、内容。记录同步存到 `output/adoptions_<时间戳>.json`
2. **终稿评分**：你把最终发布的终稿发群里，发 `评分：<终稿内容>` → 七位专家各打一个满分10分的分数 + 一句话理由，以紫色「评分」卡片推送。评分记录存入 `output/stats.json`
3. **复盘评估**：拿到实际效果数据后，发 `复盘：播放量1.2w、完播率41%、转化率0.9%…` → 阿记读取讨论记录+采纳清单+你的数据，逐条评估每条被采纳的改动（✅有效 / ⚠️部分有效 / ❌无效）+ 数据依据 + 下一步（保留/微调/回退），并给每位被评估的专家提炼**一句话正面反馈 / 一句话负面反馈**
4. **反馈闭环（自动）**：复盘结果写入 `output/stats.json` 后，程序自动：
   - 给每位专家生成**反馈档案**（负面清单：严禁再犯；正面清单：继续保持）
   - 下次任何讨论/评分时，该专家的系统提示会强制带上这份档案（`【历史反馈档案】`），确保"错过的不再错、对的延续"
   - 实时计算**历史正确率排名**（有效=1分/部分有效=0.5分/无效=0分，🥇 谁最高谁最低一目了然）
   - 结合评分记录更新**评分准确性排名**（阿记判定实际分，谁的打分偏差最小谁最准）

> 复盘分析的原则：数据不足以判断时会明确说"现有数据不足以判断"，不会编造因果。复盘报告以绿色「复盘分析」卡片推送到群里。

### 爆款文案实战吸收（七位专家持续进化）⭐

你时不时会看到一篇现成的爆款文案。把它发进来，七位专家会**各自**研读并对照自己的知识档案，提炼出**自身缺失/薄弱的实战知识点**——所有内容**落盘为实际文件**，不是嘴上说记住：

```
发 学习：<爆款文案全文>
```

- 每位专家独立精读 → 最多提炼 4 条「原文摘录 + 知识点 + 应用方法」（宁缺毋滥）
- **反 AI 幻觉硬校验**：每条「原文摘录」都必须逐字存在于你发的文案里，程序自动比对（`scripts/learn_store.py` 的 `verify_quote`）——编造或改写的摘录被**直接丢弃**并在卡片里标红计数
- 通过的条目写入 `knowledge_digests/lessons/<专家id>_lessons.md`（每人最多保留最近 30 条，超出自动淘汰最旧的），同时记入 `output/stats.json` 的 `learn_history` 审计留痕
- **下次任何讨论/评分自动生效**：每位专家的系统提示会带上【爆款实战吸收档案】，把已验证的爆款手法用进后续分析
- 想清零重来：删除 `knowledge_digests/lessons/` 目录即可

> 为什么敢说不是幻觉？因为每条知识都带着"原文证据"，且证据被程序逐字核对过——就像引用必须标注出处，找不到出处的引用一律作废。

### 对标账号监控（抖音选题雷达）⭐

盯住你的对标账号，自动找出**近 10 条视频里点赞最高的选题**，并做**两层去重 + 撞车检测**：

1. **添加对标账号**：页面顶部「📡 对标监控」→ 粘贴抖音主页链接（支持 `v.douyin.com` 短链）→ 添加。账号资料（昵称/签名/粉丝数/作品数）自动拉取，可随时删除
2. **一键抓取**：点「开始抓取」→ 逐个账号拉取主页 + 近 10 条视频（标题/简介 + 点赞/评论/播放数），账号间自动限速，进度条实时显示
3. **高赞选题榜**：所有账号近 10 条视频按点赞排序，前三名金/银/铜标色
4. **两层去重（防搬运）**：
   - **视频级去重**：同一视频（同 aweme_id）被多个账号搬运时，只保留点赞最高的一条，并在报告中列出被去重命中的记录
   - **选题级去重**：标题/简介分词 → 关键词指纹 → 相似度聚类，相似选题合并为一组
5. **撞车榜（重点）**：某个选题被 ≥2 个账号同时做（相似度高），红色卡片置顶展示——说明这选题正在被验证、值得跟进，也是你的「跟风雷达」
6. 报告自动落盘 `output/monitor/latest.md`（Markdown）+ `latest.json`（数据），每次抓取还留时间戳归档

> **首次使用前提**：需要本机 Chrome/Edge/Firefox **登录过抖音**（程序自动读取浏览器 cookie，无需手动填）。若三个浏览器都未登录抖音，抓取会提示错误；登录任意一个后重启服务即可。

## 知识内化是什么

「临时查找」→「长期内化」的升级：

1. **深度研读**：原始知识库被切块，每块交给 DeepSeek 提炼出【核心理念】【方法论框架】【可复用话术弹药库】【禁忌反例】
2. **整合沉淀**：所有块的笔记再整合成一份 2500-4500 字的《个人知识档案》，存为每个专家的"武功秘籍"
3. **讨论即用**：群聊时专家直接调用自己的档案，开口就是知识库里的专业概念和原汁原味的话术

知识库更新后，重跑一次 `knowledge_distill.py` 即可。

## 配置说明（config.json）

- `api.api_key`：不随源码或 exe 发布。首次启动后在「设置」中填写，配置会保存到当前用户的数据目录；部署时也可设置环境变量 `WB_LLM_API_KEY`。
- 数据目录：默认在 `%LOCALAPPDATA%\\靓仔文案工作台\\`（打包版沿用 `%APPDATA%\\靓仔文案工作台\\`）；可设置 `WB_DATA_DIR` 用于测试或团队隔离。
- 首次使用：打开工作台首页的「去配置 API」，保存并测试 LLM 连接后再使用专家群聊、洗稿和复盘。

## 开发与发布自检

```powershell
python -m pip install -r requirements.txt
python scripts/doctor.py
pyinstaller copywriters_chat.spec
```

`doctor.py` 不会联网，也不会打印密钥；它会检查依赖、打包配置是否仍含密钥，以及 `ffmpeg` 是否可用。
- `api.model`：默认 `deepseek-chat`
- `context`：**全局创作背景**（`user_identity` 账号主理人身份、`target_audience` 目标受众），自动注入所有专家与所有环节的 prompt，改这里即全局生效
- `agents[].persona`：专家人设，想换风格直接改这里
- `agents[].digest_path`：该专家的知识档案路径
- `recorder`：记录员配置（name/title/color/persona），想改记录员风格或换名字直接改
- `distill.max_input_chars`：蒸馏输入上限（超大知识库取前 N 字符研读）
- `distill.chunk_size`：研读分块大小
- `discussion.max_context_chars`：回退到原始知识库时的截断上限

统计数据文件：`output/stats.json`（每位专家的采纳评估历史、正/负反馈档案、正确率、评分记录、评分准确性）。想清零历史统计，删掉这个文件即可。

## 讨论流程

```
Round 1  各自独立分析（读原稿 + 自己的知识档案，给出【改写】+【理由】）
Round 2  群聊互评（回应他人观点，同样落到具体段落的【改写】+【理由】）
Round 3  各自终稿（基于完整讨论，给出最终修改版全文）
```
